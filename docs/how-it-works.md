# スニペット帳の守り方のしくみ（Version 2）

この文書は、`app/snippet-book.html` の中の鍵と暗号のしくみを説明します。コードでは `/*<core>` 〜 `/*</core>*/` の部分と、その下の「Passkey (WebAuthn PRF)」の部分にあたります。

## 1. 使っているもの

- すべてブラウザの WebCrypto（`crypto.subtle`）と WebAuthn（`navigator.credentials`）だけを使います。外部のライブラリは使いません。
- 暗号：AES-GCM（256bit）
- 鍵を作る：HKDF-SHA256（パスキー・復元キー）、PBKDF2-SHA256（ファイル専用パスワード・古い形のファイル）

## 2. 鍵の形

1. **データの鍵（DK）**：開くたびではなく、最初に 1 回だけ `crypto.getRandomValues` で作る 32 バイト。登録した内容はすべてこの鍵で AES-GCM 暗号化します。DK そのものは保存しません。ロックするとメモリから消します（0 で埋める）。
2. **パスキーで包む**
   - パスキーの登録で、PRF 拡張の入力（32 バイトのでたらめ）を決めます。
   - 本人確認すると、パスキーが PRF の値（32 バイト）を返します。この値は、パスキーとこのドメイン（`snippet.eiwa-up.jp`）と入力の組み合わせでしか出てきません。
   - `HKDF-SHA256(PRF の値, salt=でたらめ 16 バイト, info="snippet-book/v5/passkey")` で包む鍵を作り、DK を AES-GCM で暗号化（包む）します。
3. **復元キーで包む**
   - 復元キーは 25 文字。Crockford Base32 の 32 文字から選ぶので 5bit × 25 = 125bit です（1 バイトの下 5 ビットを使うので偏りません）。
   - 読むときは小文字・空白・`-` を許し、`O` は `0`、`I` と `L` は `1` として読みます。
   - `HKDF-SHA256(復元キー, salt=でたらめ 16 バイト, info="snippet-book/v5/recovery")` で包む鍵を作り、DK を包みます。
   - 125bit のでたらめなので、総当たりで探すことは実際にはできません。そのため PBKDF2 のような重い計算はしていません。

どちらの包みをほどいても、同じ DK が出てきます。

## 3. 保存するもの

この端末の中（localStorage）：

```
snippet-book:v5:meta = {
  version: 5,
  vaultId: でたらめ 16 バイト（base64url）,
  wraps: [
    { type: "recovery", salt, iv, ct, created },
    { type: "passkey", credId, prfSalt, label, salt, iv, ct, created },
    …
  ],
  data: { iv, ct },  // DK で暗号化した中身（2.00.008〜 同じ項目に入れる）
  revoked: [credId, …]  // 外したパスキー（2.00.009〜 バックアップにも入れる）
}
```

バックアップファイル：

```
{ version: 5, enc: "aes-gcm", kdf: "dk-wrap", mode, role?, name, vaultId, wraps: [...], iv, ct }
```

- `wraps` には、包んだ DK だけが入ります。**PRF の値と復元キーそのものは、どこにも保存しません。**
- だから、バックアップファイルだけでは中身を読めません。パスキー（同期したものを含む）か復元キーが要ります。
- AES-GCM なので、中身を 1 ビットでも書きかえられたら開けません。

## 4. パスキーについて

- `rp.id` はページのドメイン（`snippet.eiwa-up.jp`）です。ほかのドメインからは、このパスキーの PRF の値を取り出せません。
- 登録は `residentKey: required`、`userVerification: required`、`attestation: none`。
- サーバーは使いません。チャレンジはその場で作るだけで、確かめる相手もいません。パスキーは「本人確認して PRF の値を取り出す」ためだけに使っています。
- 登録のときに PRF の値を返さない環境があるので、登録のすぐ後に 1 回だけ本人確認して値を取り出します。
- PRF に対応していない環境では、登録できたように見えても `prf.enabled` が `false` になります。そのときは包みを作らず、「対応していません」と知らせます。
- 同じ端末に二重に登録しないよう、`excludeCredentials` に登録済みのものを渡します。

## 5. 守れるもの・守れないもの

| 起きること | 結果 |
|---|---|
| バックアップファイルを盗まれ、総当たりされる | 読まれない（鍵が長いでたらめなため） |
| 開くときにのぞき見・キー入力を盗まれる | 打つものが無いので取られない（パスキーのとき） |
| ロックが外れた端末を取られる | パスキーで開けてしまう（端末のロックが大事） |
| 復元キーとバックアップを両方取られる | 読まれる（別々にしまうこと） |
| ページに悪いスクリプトを書き足される（XSS など） | CSP でスクリプトをハッシュ値の 1 つだけに決めているので、書き足されたスクリプトは動かない（2.00.003〜） |
| 配っているページそのものを書きかえられる | 読まれる。開く前には止められない。verify（1 時間に 1 回）があとで気づく。更新できる人を持ち主 1 人に絞り、配る側のアカウント（サーバー・GitHub・ドメイン）を二段階認証などで守ることで防ぐ |
| 「このセットを暗号化して送る」のファイルを手に入れ、パスワードを総当たりされる | 2.00.003〜 は 20 文字（約 99 ビット）なので現実には破れない。2.00.002 までのパスワード（約 24.5 ビット）で作ったファイルは、強い GPU なら数十分〜数時間で破られうる |

## 6. ほかのファイル

- **セット送信・ファイル専用パスワード**：パスワードから PBKDF2-SHA256 で鍵を作ります。新しく作るファイルは 60 万回で、回数をファイルに書きます。
  - セット送信のパスワードは、アプリが作ります（2.00.003〜）：`23456789ABCDEFGHJKMNPQRSTUVWXYZ` の 31 文字から 20 文字（約 99.1 ビット）。`crypto.getRandomValues` の 1 バイトのうち 248 以上を捨てて偏りをなくし、5 文字ずつ `-` で区切ります（`-` もパスワードの一部）。2.00.002 までは「32 語から 3 つ＋2 けたの数字＋記号 8 種」（約 2,359 万通り・約 24.5 ビット）で弱かったため変えました。
  - ファイル専用パスワード（人が決めるもの）は 12 文字以上です（2.00.002 までは 8 文字以上）。
- **Version 1 のファイル**：PBKDF2-SHA256 25 万回（回数の記録なし）として開きます。取り込みのときだけ使います。

## 6-2. 開いている間の守り（2.00.004〜）

- **自動ロック**：何もしない時間（押す・打つ・スクロールなどが無い時間）が決めた分（1・5・15・30 分・しない。はじめは 5 分）を超えたらロックし、データの鍵をメモリから消します。別のタブ・アプリに移っている間も数えます。10 秒ごとと、画面に戻ったときに確かめます。保存待ちの変更は、鍵を消す前に書きます。復元キーを見せている画面の間はロックしません。
- **ロックで画面を空にする（2.00.005〜）**：ロック（手でも自動でも同じ `lockNow`）では、データの鍵を消したすぐあとに `wipeScreen` を呼び、ページの DOM から平文をすべて消します。カードと編集欄（パスワード欄の値も）・セットの名前・検索の文字・データ名・状態の表示（コピーした文の頭）・トースト・人に送るパスワードの画面・バックアップ完了の画面・鍵の設定の画面・復元キーの画面と入力欄・ファイルを開く画面で打った復元キー・印刷用の欄です。開いている途中の画面は、待っている処理も終わらせます。ファイルを開く画面の復元キーは、開けた・やめたときにも消します。
  - JavaScript の文字列はブラウザが後で片づけるため、メモリから消える時期までは決められません。
- **途中でロックしたら何もしない（2.00.006〜）**：ロックのたびに番号（`lockEpoch`）を1つ進めます（`lockNow` のいちばん最初）。時間のかかる処理（セット送信・全体の書き出し・上書きバックアップ・読み込み・コピー・パスキーの登録）は、始めたときの番号を覚え、`await` のあとに番号が変わっていたら、画面を出さず・ファイルを書き出さず・データに足さずに終わります。コピーでは、クリップボードを空にする予定だけは立てます。
- **鍵の作業と途中のロック（2.00.007〜）**：パスキーの登録・復元キーの作り直し・鍵をすべて作り直す・新しく作るは、時間のかかる計算（包む・暗号化）を先に、まわりを変えずにすませます。そのあとロックの番号を確かめ、変わっていなければ、`await` をはさまずに、データと鍵を書き、画面を出します（2.00.008 からは1つの項目に1回で書きます）。こうすると、書きこみの途中にロックが割りこめず、データと鍵がずれません。2.00.006 までは、鍵をすべて作り直すの最後の処理の途中でロックすると、ロックのあとにアプリが開き直ることがありました。
- **クリップボード**：パスワード・復元キー・セット送信のパスワードをコピーしたら、30 秒（または「空にしない」）のあとに空にします。ブラウザは前に出ていないページからクリップボードに書けないので、そのときは予定を残し、画面に戻って触ったときに空にします。**戻らなければ残ります。** この画面でほかの物をコピーしたら予定は取り消します。クリップボードの履歴（Windows の Win＋V・履歴アプリ）や共有クリップボードに入った分は消せません。
- **データと鍵を1回で書く（2.00.008〜）**：鍵の情報（`wraps`）と暗号化した中身（`data`）を `snippet-book:v5:meta` の1つの項目にまとめ、1回の `localStorage.setItem` で書きます。1回の書きこみは「全部入れかわるか、何も変わらないか」なので、片方だけ書けてずれることがありません。書けなかったら（容量いっぱいなど）何も変えずに知らせ、書けてから使う鍵や画面を切りかえます。2.00.007 までは中身を `snippet-book:v5:data` に別に書いていたので、鍵をすべて作り直すときに中身の書きこみだけ失敗すると、鍵の情報だけ新しくなって開けなくなることがありました。前の形も読めて、開いたときに新しい形へ移し、前の項目は消します。
- **パスキーの一覧を合わせる（2.00.009〜）**：パスキーの一覧（`wraps` の `passkey`）は端末ごとに持ちます。同じ金庫（`vaultId` が同じ）のバックアップで、🔑 鍵 の「ほかの端末のパスキーを合わせる」または「上書き用バックアップから開く」を使うと、一覧を合わせます。合わせるのはパスキーだけで、復元キーの包みはその端末のものを使います（作り直した古い復元キーを戻さないため）。外したパスキーの `credId` は `revoked` に残してバックアップにも入れ、どちらの側で外したものも戻しません。合わせる前に、そのファイルの中身がいまの DK で開けること（AES-GCM の確かめ）を見て、本物のファイルだけを受けつけます。
- **開けないときに上書きしない（2.00.008〜）**：鍵は合ったのに中身を復号できないときは、鍵をメモリから消してロック画面のまま知らせ、データには手を付けません（2.00.007 までは見本のデータで上書きして保存していました）。
- 設定は `localStorage` の `snippet-book:v5:prefs` に平文で置きます（中身ではないため）。

## 6-3. 読み込むファイルの検査（2.00.004〜）

- 5MB を超えるファイルは読みません。セットは 200、カードは 10,000 までです。
- 読み込んだ値は、文字と数だけを文字として使い、それ以外は空にします（形のおかしいファイルで画面が止まらないように）。保存から読むときも同じです。
- 先に全体を整えて確かめ、だめなら何も足しません。
- 画面に出すときは文字を無害にし（エスケープ）、そのうえ CSP でも書き足されたスクリプトは動きません。

## 7. 配り方

- `https://snippet.eiwa-up.jp/` から配っています。nginx の設定は [`deploy/snippet.conf`](../deploy/snippet.conf) です。
- CSP は `default-src 'none'`、`script-src 'sha256-…'`（HTML の中のスクリプト 1 つのハッシュ値）、`style-src 'unsafe-inline'`、`font-src 'self'`、`img-src 'self' data:`、`connect-src 'none'`、`frame-ancestors 'none'` などです。
  - 版を上げてスクリプトが変わるたびに、CSP のハッシュ値も書きかえます（`tests/test-v2009.mjs` が合っているか確かめます）。
  - スタイルのインラインは許しています（画面の部品の見た目に使うため）。
- 2.00.003 から、文字の形（IBM Plex Mono）も同じサイトの `fonts/` から読みます。ほかのサイトからは何も読み込みません。日本語の文字は端末に入っている文字の形を使います。
- CSP は、リンクを開く・画面を移るといった動きまでは止めません。「外への通信がまったく無い」とは言えないので、「登録した内容を外へ送るしくみが無い」と説明しています。
- 配っている中身と CSP がこのリポジトリと同じかは、`.github/workflows/verify.yml` が 1 時間に 1 回確かめます。
